### Findings

1. **crates/app/ui/src/main.ts:3429-3438 (`saveFormat`)**: The order of the two invokes defeats the requirement that the dialog not close for good without a language (implementer's edge case (a)). `sidecarFormat` is the one key that gates the dialog, so it should be written *last*, not first. As written, if `choose_sidecar_format` succeeds and `set_label_names` rejects (its only `Err` path is the `reset_sidecars` / `spawn_blocking` step), quitting at that point means the next launch skips the dialog and the names stay English. `set_label_names` also only logs a failed `labelNames` store save and still returns `Ok`, so a failed save of the names goes unnoticed in either order. The simple fix is to swap the chain: `set_label_names` first (when `names !== null`), then `choose_sidecar_format`. Then a `set_label_names` rejection leaves the format unsaved, so the dialog comes back. And because the store's `save()` writes the whole in-memory store, the following `choose_sidecar_format` save also persists `labelNames` that `set_label_names` failed to write. If that save fails too, `choose_sidecar_format` returns the error and the dialog stays open. Applying the names before the format has no side effect, because `set_label_names`'s `sidecar-format` emit is harmless while no folder is open (the plan already says so). Update the comment above `saveFormat`, whose reasoning ("format first, it is what keeps the dialog from coming back") is the argument for putting it last. Also update the matching bullet in `learnings.md`, and add a line to the plan's Step 4 approach saying the order was reversed and why.

2. **crates/app/ui/src/main.ts:3412-3422, 3473-3479 (`showFormatDialog` / `Continue`)**: When `formatPresets` holds no preset matching the select, `Continue` calls `saveFormat(chosenFormat, null, ...)`, which saves XMP / Both without a language and closes the dialog. That is the "require choosing Lightroom's UI language before the dialog closes" requirement failing outright (implementer's edge case (b)). It is not only the IPC-failure case: the `label_names` fetch in `showFormatDialog` is not awaited before the buttons work, so a fast Lightroom click followed by Enter/Continue can also get there before the presets arrive. The `label_names` invoke in `showFormatDialog` also has no rejection handler, so a failure is an unhandled rejection and the user sees nothing. Simple fix: in the `Continue` handler, `return` without saving when `preset` is undefined (so `names === null` only ever means DxO). Add a rejection handler to the `label_names` invoke that puts the error in `#format-error` (unhidden), as the save path does. The user then stays in the dialog and can still pick DxO. Optionally, keep `formatContinue.disabled` until the presets have loaded.
