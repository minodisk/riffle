STATUS: NEEDS_FIX

### Findings

1. **crates/app/ui/src/folders.ts:225-236 (with main.ts:2614-2623, treekeys.ts:1-4)**: `typeKey` consumes every printable key (length-1 `event.key` with no Ctrl / Alt / Meta, Shift included) before `main.ts` gets to consult `treeGate`. That breaks the invariant `treekeys.ts` states ("Keyed by action name so it holds however the keys are rebound"). If a user rebinds a passthrough action (`toggleSides`, `toggleLeft`, `toggleRight`, `toggleStrip`, or `open`) to a printable key such as `\`, `shift+s` or a plain letter, that action silently stops working while the tree has focus, even though Step 1 promised, and Step 4 will document, that the pane toggles and Open Folder still work there. Suggested fix: in `main.ts`, look up the keymap action before handing the key to type-ahead, and let `treeGate(action) === "run"` win over type-ahead. For example, check `keymap.get(key)` against `TREE_PASSTHROUGH` before calling `folders.keydown`, or pass a predicate into `folders.keydown` so `typeKey` returns false for a passthrough-bound key. Add a test for the precedence if it lives in a pure function. If you choose to keep type-ahead winning, say so in `learnings.md` and in Step 4's docs ("a pane toggle rebound to a printable key is taken by type-ahead while the tree is focused") so the documented allowlist is not wrong.

1. The plan also already assigns writing this up to Step 4 ("Documented in `usage.md`'s fixed-keys note"), which is still `[ ]` (not yet implemented) — so there is nothing to fix in this step, and no stale doc to correct yet.
