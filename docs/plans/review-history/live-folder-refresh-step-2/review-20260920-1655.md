# Review: live-folder-refresh-step-2

## Round 1

**Reviewed commit**: `b7fddb0b45636ae60a377ffc106d636ec64dae0a` feat(app): watch the open folder and rescan on change

STATUS: NEEDS_FIX

### Findings

1. **[crates/app/src/watch.rs:97 + crates/app/ui/src/main.ts:1193]**: The
   `folder-changed` payload carries the **canonicalised** directory
   (`scan_folder` does `let dir = canonicalize(&dir); crate::watch::set(&app, &dir);`,
   and `set` stores that string as the event `owner`), but the frontend
   compares it with `openDir`, which is the path as picked / passed in
   (`openDirectory(folder, token)` sets `openDir = folder`; nothing on the
   frontend canonicalises). Whenever the two differ, `payload.dir !== openDir`
   is always true and the live refresh silently never fires — the feature
   degrades to Step 1's focus rescan with no log and no visible symptom. This
   is not hypothetical on Windows, where `std::fs::canonicalize` returns a
   verbatim path (`\\?\C:\photos` vs `C:\photos`), and it also bites on any
   symlinked parent on macOS (`/tmp/...`, a symlinked home or volume mount).
   Suggested fix: keep watching the canonical path but emit the *caller's*
   `dir` — capture the original `dir` in `scan_folder` before the shadowing
   `canonicalize` and pass it to `watch::set` as the payload owner (`set(&app,
   &canonical, &original)`), so the payload is exactly the string the frontend
   holds in `openDir`. (Alternatively make the frontend adopt a
   backend-canonicalised `openDir`, but that touches every other `dir`
   comparison, so the first option is the surgical one.)
