### Findings

1. **crates/app/ui/style.css:680 (`.folder .name`)**: A long folder name no longer ellipsizes. A grid item whose `justify-self` is not `stretch` gets a fit-content width, `max(min-content, min(max-content, stretch-fit))`. With the row's `white-space: nowrap`, min-content is the full text width, so the span is as wide as its text no matter how narrow the `minmax(0, 1fr)` column is. `min-width: 0` does not cap it. The flex version relied on `flex-shrink` with `min-width: 0`, which a grid item does not have. As a result the name runs past its column, over the `max-content` count badge and the row's right padding. `text-overflow: ellipsis` never fires because the span is never narrower than its content, and `#folders` (`overflow: auto`) gains a horizontal scrollbar. This breaks the Done-when "a long name ellipsizing before its badge", and the learnings note about ellipsizing "2px earlier" assumes it still works. Fix: add `max-width: 100%` to `.folder .name`. The percentage resolves against the grid area, so the span still hugs a short name but is capped at the column. Optionally mention this in the guide's `.folder` bullet in `docs/agents/ui-styling.md`.
2. **crates/app/ui/style.css:671-672, 703-705 (`.folder .expander` / `.folder .count`)**: Now that `.folder` is a grid, `flex: none` does nothing on either child. The `.folder .count` rule is left holding only that dead declaration under its comment. This change orphaned them, so remove them: drop the `.folder .count` rule, or give it something real to hold, and drop `flex: none` from `.folder .expander`. Its width comes from the `14px` column and its own `width: 14px`.
