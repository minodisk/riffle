### Findings

1. **crates/app/ui/src/main.ts:819-827**: the `sidecar-error` listener is the one new async path with no folder check at all. The writer is shared across folders and flushes its debounce after the user has moved on, so an error for a file of the previous folder lands in the status line of the new one, naming a file that is not in view. `docs/agents/tauri-app.md` ("Give the current folder one token") asks every path that can outlive its folder to check before applying. The payload carries no `dir`, so gate on the path belonging to the open folder, e.g. `if (!fileIndex.has(payload.path)) return;` before `setStatus`.

2. **crates/app/ui/src/main.ts:333-356**: `refreshEntries` guards its response with `dir !== openDir`, which does not catch a reopen of the *same* folder — a case this file already knows is live (the `scanId` comment calls out "cancelled by reopening the very same folder"). That was tolerable while the response only refilled `entries`, but it now writes into `ratings` after `openDirectory` has cleared `ratings` and `touched`, so a response from the previous open can repaint badges from a snapshot the new open has already discarded. Capture `const token = folderToken;` alongside `const dir = openDir;` and check `token !== folderToken` too (no new counter, per the same guide entry).

3. **crates/app/ui/src/main.ts:314-322**: the revert path does not remove the path from `touched`, so a rating whose invoke failed stays pinned for the rest of the session and no later `folder_entries` refresh — including the authoritative `scan-done` one — can ever correct it. Since the revert restores exactly the value the index still holds, `touched.delete(path)` in the `catch` (before or after `applyRating(path, previous)`) is safe and closes the gap.

4. **crates/app/ui/src/main.ts:867-871**: the `u` branch reads `files[index]` without the `files.length === 0` guard that `rate()` performs, so on an empty folder it evaluates `ratings.get(undefined)` while the type says `string`. Harmless today only because `Map.get` tolerates it; add the `files.length === 0` check (or read the same `ratings.get(files[index] ?? "")`) so the branch is not relying on a typed lie.
