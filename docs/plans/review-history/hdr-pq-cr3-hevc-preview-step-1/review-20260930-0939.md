## Round 1

**Reviewed commit**: `2825d5722fb739af65b7fbe82829e93c7986402a` feat(core): decode the HEVC PRVW / THMB of HDR PQ CR3 files to a JPEG

STATUS: NEEDS_FIX

### Findings

1. **crates/core/src/reader.rs:178-181 (`embedded_from`) with :112-122 (`read_embedded`)**: `hevc::to_jpeg` now runs inside `embedded_from`, so its errors also reach `read_embedded`'s `Err(_) if bounded` fallback. That fallback assumes the only error it can see comes from a prefix that was cut short ("The prefix error only explains a truncated read"). An HEVC stream that hpvcd rejects, or a frame that `to_rgb` refuses (8-bit, monochrome, smaller than its header), is not a truncation problem. Every real HDR PQ CR3 is longer than `HEAD_LIMIT`, so for each such file `read_preview` / `read_full` read the whole file (tens of MB), parse it again and run the ~100 ms decode a second time, only to hit the same error. The scan does this once per affected file, and so does every view. Suggested fix: keep `embedded_from` returning the raw embedded bytes plus the `Codec` (or the `Embedded`), and run `hevc::to_jpeg` once in `read_embedded` after the prefix / whole-file `match` resolves. Only range and parse errors should trigger the retry. Add a reader test that uses a bounded file (the existing `hevc-far.CR3` case already is one) to check that a decode error surfaces without the retry. For example, assert the error text is unchanged while the file can only be read once, or restructure so the retry path is not taken by construction.
