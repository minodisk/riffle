### Findings

1. **[crates/app/src/commands.rs:368, 390]**: `mcpEnabled` is parsed with `auto_advance_setting(...)`, both on the store-failure fallback and on the normal path. The function's doc says "The stored `autoAdvance` value", so `auto_advance_setting(store.get("mcpEnabled"))` reads as a bug, and a later change to how `autoAdvance` is interpreted would silently change the MCP setting too. Add a `mcp_enabled_setting` next to it (or use `store.get("mcpEnabled").as_ref().and_then(Value::as_bool).unwrap_or(false)` inline, and `false` in the fallback tuple) so each setting has its own parser.
2. **[crates/app/src/mcp.rs:222]**: The test `start_binds_the_port_and_stop_frees_it` never calls `start`. It builds `Running` through `serve` on an ephemeral port and checks `bind` / `stop`, so its name claims coverage that the test does not have. `start`'s early return when a server is already running (the path that stops a second toggle from binding twice) is also untested. Rename it to match what it runs (for example `serve_binds_the_port_and_stop_frees_it`). Also add a test that `start` returns the running port without binding again when `status.running` is already `Some`. That test can seed `Status.running` from `serve` on an ephemeral port, as the existing test does.
