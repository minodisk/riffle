### Findings

1. **crates/app/src/exif.rs:54-73 (`focus_mode` / `af_tracking`)**: ExifTool's Sony.pm puts a model condition on both `FocusMode` (0x201b) and `AFTracking` (0x2021): `($$self{Model} !~ /^DSC-/) or ($$self{Model} =~ /^DSC-(RX10M4|RX100M6|RX100M7|RX100M5A|HX95|HX99|RX0M2|RX1RM3)/)`. Its comment on 0x201b says the tag "doesn't seem to apply to DSC models (always 0)". So on older RX bodies that write ARW (for example DSC-RX100M3/M4/M5, RX10M2/M3, RX1RM2), the meta pane would show "Manual" and "Off", which are wrong. The plan's Purpose also says "none of the new tags has a model condition except `AFAreaModeSetting`", and that is inaccurate. Suggested fix: give `focus_mode` and `af_tracking` the same `model: Option<&str>` gate that `af_area` has. Return `None` for a `DSC-` model unless it matches one of ExifTool's listed prefixes, and add a unit test (e.g. `DSC-RX100M3` gives `None`, `DSC-RX100M7` and `ILCE-7M5` give the label). If you would rather keep the scope narrow, the other option is to gate `DSC-` out entirely, as `af_area` already does. Either way, correct the plan's Purpose sentence. The same `focus_mode == Some(0)` read in `crates/core/src/sharpness.rs` is pre-existing and out of scope, but worth a deferred-issue note in `learnings.md`.
2. **crates/app/src/exif.rs:71 (and the test at :253)**: ExifTool's label for `AFTracking` 2 is `'Lock On AF'`, with no hyphen. Sony.pm reads `2 => 'Lock On AF'`. The plan's approach says "Label wording follows ExifTool", and the doc comment says it is "labeled as ExifTool's Sony.pm". Either change it to `"Lock On AF"` (and update the plan's Purpose list), or keep Sony's own "Lock-on AF" style and change the doc comment so it no longer claims ExifTool wording for this value.
