### Findings

1. **[crates/core/src/i18n.rs:7-11]**: The module doc says "a missing key reads as `en.json`'s value", but the code does nothing like that for any key that exists today. A file without `meta.name` fails to deserialize and panics in `presets()`. A `colorLabels` object missing one color (for example `purple`) also fails to parse and panics; it does not fall back to `"Purple"`. A file without `colorLabels` gets no preset at all, not English's. The next sentence ("this reduces to 'a language without `colorLabels` offers no preset'") contradicts the general rule instead of following from it. Step 3's contributor README will be based on this comment, so it should describe what actually happens. Suggested fix: reword it to say that `meta.name` is required, that `lightroom.colorLabels` is all-or-nothing (all five colors plus `verified`, or omitted, in which case the language offers no preset), and that falling back to `en.json` per key is only the intended rule for future namespaces, not something any current key does.
