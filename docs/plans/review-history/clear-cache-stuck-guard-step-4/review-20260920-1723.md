### Findings

1. **docs/agents/tauri-app.md:457-458**: The new `(Hit)` entry says `is_some()`
   was fine for "`spawn_eviction`, which runs once before any scan can exist".
   A scan *can* exist by then: `spawn_eviction` runs on its own thread spawned
   from `setup`, and `commands.rs`'s `if state.running.is_some() { return; }`
   exists precisely because a `scan_folder` may have won the race. This also
   contradicts the amended eviction paragraph two hundred lines up, which
   frames the same check as "a scan was started". Reword to the accurate
   reason, e.g. "`spawn_eviction`, which only needs to know whether a scan has
   been started at all, and skips if so".
2. **docs/agents/tauri-app.md:405-407**: In the amended eviction paragraph,
   "which at that point in `setup` can only mean a scan was started, since
   nothing else has run yet" hangs the correctness on a point in `setup`, but
   the check runs on a detached thread that can take the lock at any later
   moment. The load-bearing fact is that `running` is only ever *set* by
   `start_scan`, so `is_some()` there means "a scan has been started" (and
   never cleared) — say that instead of tying it to `setup`'s timeline.
3. **docs/agents/tauri-app.md:408**: The amended sentence leaves a 113-column
   line ("A `scan_folder`/`start_scan` issued meanwhile just waits. Keep the
   order `Scans` then writer. The size cap counts") in a file whose prose wraps
   at ~76. Markdown is excluded from the formatter (`vite.config.ts`'s
   `fmt.ignorePatterns` has `**/*.md`), so no linter will fix it; re-wrap the
   paragraph by hand.
