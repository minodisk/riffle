### Findings

1. **[crates/core/src/rank.rs:412-423, docs/humans/usage.md:626 (and usage.ja.md:50, rank.rs module doc lines 9-12)]**: Nothing checks the claim that a few finished folders leave the model close to the prior. The pull toward the prior is `tau = 1/(2C)` = 5 in total. Each burst's pairs weigh 1, so the 1801 bursts behind the prior count for nothing in the refit, and the prior's whole weight is about what a dozen or two bursts contribute to the Hessian (each burst adds about `0.25 * |diff|^2` per direction). One finished folder of about 70 scorable bursts therefore outweighs the prior several times over, and its 44 weights can move a long way. A rough estimate puts the L2 move on the order of the prior's norm of 1.37. The one measured move (0.300) comes from 1602 bursts that agree with the prior, so it says nothing about the one-to-three-folder case that a new user hits first. `ranking.md` does not show whether that case is better or worse than the prior alone. Either (a) measure it, e.g. in `the_scores_match_rank_prior_py` or `gate.py`: refit from the prior on 1, 3 and 5 folders and compare the held-out weighted AUC with the prior's, recording the result in `ranking.md`, and pick the pull strength from that (for example tau scaled by the prior's burst count, or by a chosen pseudo-count); or (b) remove the "stays close to the built-in model" / "a few finished folders move the model a little" wording from the user docs and the module doc, and record the untested shrinkage strength as a deferred issue in `learnings.md`.

Make the text describe what the number measures, e.g. `Built-in only, nothing learned yet` (update usage.md / usage.ja.md and meta.test.ts to match).
