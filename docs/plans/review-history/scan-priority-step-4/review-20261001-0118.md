## Round 1

**Reviewed commit**: `89f466009883ac944b12d38f5b4c3469b2234a25` feat(core): run the scan's workers below normal OS priority, the analysis pass lowest

STATUS: NEEDS_FIX

### Findings

1. **crates/core/src/scan.rs:293-302 (Linux `lower_current_priority`)**: `setpriority(PRIO_PROCESS, 0, 5 | 10)` sets an absolute nice value, not a lowering relative to the thread's current nice. The per-thread claim holds on Linux (`who == 0` means the calling thread), but a new thread inherits its creator's nice. So if the process already runs at nice > 5 (for example started with `nice -n 10`, or `cargo test` run under `nice`), `BelowNormal` tries to *decrease* nice. For an unprivileged user that fails with `EACCES`. The app then logs a misleading "ran at normal priority" warning on every scan, even though the workers were already below normal. And `every_index_is_delivered_once` / `every_worker_runs_at_the_priority_it_was_given` fail their `Ok(None)` assertion. With `CAP_SYS_NICE` (root, which is common in container CI), the call succeeds and *raises* the workers above the rest of the process, which is the opposite of the intent. Suggested fix: read the thread's current nice first (`getpriority`, clearing `errno` before the call since `-1` is a valid return value), then set `max(current, target)` or `min(current + delta, 19)`. Make `expected_level` in the Linux test relative to the test thread's own nice in the same way.
2. **crates/core/src/scan.rs:293 (`#[cfg(all(unix, not(target_os = "macos")))]`)**: this branch covers every non-macOS unix (FreeBSD, NetBSD, OpenBSD, illumos, etc.). On those systems `setpriority(PRIO_PROCESS, 0, ..)` renices the whole process, UI threads included, and only Linux (and Android) has the thread-only behavior the SAFETY comment relies on. Suggested fix: gate this branch on `any(target_os = "linux", target_os = "android")`. Widen the no-op fallback's cfg to cover all other targets (e.g. `not(any(windows, target_os = "macos", target_os = "linux", target_os = "android"))`), so the claim in the comment matches every target the code compiles for.

### Fixed

1. The Linux branch now reads the thread's current nice and sets `max(current, target)`; the test's expected level is relative to the test thread's own nice.
2. The branch is gated on `linux` / `android`, and the no-op fallback covers every other target.
