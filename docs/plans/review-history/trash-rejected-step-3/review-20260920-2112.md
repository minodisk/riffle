### Findings

1. **README.md:95-97**: "restoring one from there brings back its sidecar and with it the stars, the flag and the colour label it had" over-promises: the RAW and each sidecar are moved to the Trash as separate files, so restoring the RAW alone does not bring the sidecar back — the user has to restore the sidecars too. Reword to something like "nothing is deleted: the file and its sidecars all go to the Trash, so restoring them brings back the stars, the flag and the colour label".
2. **README.md:97-99**: "Any file that could not be moved is listed as an error and stays in the folder with its sidecars" is only true when the RAW itself fails. `trash::run` moves the RAW first and, on success, keeps going through the sidecars, so a sidecar failure leaves that sidecar in the folder while its RAW is already in the Trash. Either narrow the sentence to the file that failed ("whatever could not be moved is listed as an error and stays in the folder") or drop the "with its sidecars" clause.
