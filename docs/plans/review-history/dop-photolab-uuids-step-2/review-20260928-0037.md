### Findings

1. **crates/app/src/photolab.rs:152**: `folder_names` ends with `(names.len() > 1 && names[0].ends_with(':')).then_some(names)`. The `> 1` rejects a RAW sitting directly at a drive root (`E:\_DSC0001.ARW`, whose names are just `["E:"]`). PhotoLab registers such a file as a `Sources` row whose `FolderId` is the `E:` root row, so the lookup could resolve it, but it returns `None`. That file then gets random Uuids and turns into the virtual copy this step is meant to prevent. The doc comment ("`None` for a path not under a plain drive letter") also says a drive-root file should resolve. The `split_first().expect(...)` in `query` only needs one element, so relax the condition to `!names.is_empty() && names[0].ends_with(':')`. Then add a drive-root case to the fixture, for example a source under folder id 7 checked with `lookup(&db, Path::new(r"D:\_DSC0001.ARW"))`.
