### Findings

1. **crates/core/src/decode.rs:726**: `preview_jpeg_unguarded` rotates the image with `apply_orientation`, which only handles 6 and 8 and passes orientation 3 (a half turn) through unchanged. The `faces.rs:291` doc comment says exactly this ("`apply_orientation` leaves orientation 3 alone, so the half turn is done here"). The app itself draws orientation 3 upright (`main.ts:556`, `main.ts:616`), and the `get_preview` description promises "a small upright JPEG". So a photo taken upside down (a Leica DNG, or an ARW with Orientation 3) reaches the MCP client upside down, and the assistant would judge a different image from the one the user sees. Fix: use `crate::faces::upright_rgb` (or move that half-turn logic into `decode`) instead of `apply_orientation`. Add a `preview_jpeg(.., 3, ..)` test that checks the source's top edge ends up at the bottom, like `preview_is_rotated_upright` does for 6.
