### Findings

1. **[.claude/skills/merge-settings/scripts/merge.js:236]**: Because of `mergedLocals.length === 0`, any non-empty `settings.local.json` forces a write, even when it adds nothing. That covers the common case where every local entry is excluded (`Read(//tmp/...)`, `Bash(gh ... view *)`, a scratchpad script) or already present. The write then runs `normalizeArray`'s sort over the destination. I checked this against the repo's real `.claude/settings.json`, which is not in normalized order: with a local of `{"permissions":{"allow":["Read(//tmp/x/**)"]}}`, `merge.js --self --write` prints `Added permissions.allow: 0` and then `Wrote:`, leaving a reorder-only diff (2 insertions, 2 deletions). `commit-settings.sh` would commit that diff. It is the same no-op churn the plan's Purpose sets out to remove ("a run with nothing to add leaves `.claude/settings.json` byte-for-byte unchanged so no promotion commit is made"). The `unchanged` comparison already detects every real change, local contributions included, so drop `mergedLocals.length === 0` (and arguably `addedTotal === 0`, which `unchanged` implies) from the skip condition. `settings-promoter` is unaffected, because its step 3 empties the local on `NO_CHANGES` too. Also adjust the SKILL.md paragraph at line 70, and change step 3 at line 86 so that on `Nothing to write` the skill still empties any `settings.local.json` listed in `Merged settings.local.json:` (the commit and PR are still skipped). Add a `merge.test.sh` case: a local with only an excluded entry, checked with `expect_unchanged`.

1. Dropped `addedTotal === 0 && mergedLocals.length === 0` from the skip condition in `merge.js` (now just `unchanged`), updated SKILL.md (paragraph and step 3, which now still empties the merged local files on `Nothing to write`), and added a `merge.test.sh` case for a local with only an excluded entry.
