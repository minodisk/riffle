## Round 1

**Reviewed commit**: `c81ac23fc126794760aed5e33a03f0131958547d` fix(app): move the selection with the focus on a single-file undo / redo

STATUS: NEEDS_FIX

### Findings

1. **crates/app/ui/src/main.ts:1329**: This breaks undo / redo in compare mode. There, `judge()` records only `compareActivePath`, and that can differ from `files[index]` because clicking a pane sets `compareActivePath` without moving `index`. In compare mode, `compareCandidates()` → `comparisonCandidates(files, index, selection.selected, …)` uses the multi-selection as the comparison set. Example: select {A, B, C} with focus on A, press Compare, click pane B, judge, then press Ctrl+Z. Now `path = B !== shownPath = A`, so `restore` collapses the selection to `single(B)`. The `show()` that follows calls `loadCompare()` with a one-file selection. The comparison then switches to B's burst pair, or calls `stopComparing()` if B has no burst partner. Before this change, the selection stayed and the same set was re-compared. The plan's trade-off section says compare mode can hold a multi-selection during a single-file entry, but the `path !== shownPath` gate does not protect that case, because the compare-active pane is not the focused file. Fix: skip the collapse while comparing, for example `if (!comparing) { selection = restore(...); paintSelection(); }`, or give `restore` a flag for it. Also update the comment above `step()`.
