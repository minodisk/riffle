### Findings

1. **crates/app/ui/src/main.ts:648-656, 736-741**: Before this change, a Sequence folder-level error went through `setStatus(...)`, which replaced whatever gray note was showing. Both new paths call `renderMeta()` directly and leave `note` alone, so an older note stays visible next to the new orange error. For example, run Sequence on folder A ("Wrote 3 of 3 files to A-sequenced" becomes the note), then right-click a JPEG-free folder B and run it again. The meta pane now shows A's success headline in gray right above B's error, and that lasts until the next paging or decode clears the note (`setStatus()` at main.ts:1883/1911). That is the same "success and failure look alike" confusion this PR sets out to remove. The fix is one line: call `setStatus()` (no argument: it clears `note` and re-renders) instead of `renderMeta()` in `failSequence` and in the `status === null` branch of `finishSequence`. That branch then becomes `setStatus(doneStatus(payload) ?? undefined)`.
