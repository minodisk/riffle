## Round 1

**Reviewed commit**: `3d8662509a80199171703844538d628b321b656d` feat(app): add a Genre filter section from the image embeddings

STATUS: NEEDS_FIX

### Findings

1. **[crates/app/ui/src/main.ts:2283 / 2293 (refreshEntries), 3525-3560 (folder open)]**: `fileGenres` is never reset when a folder opens, and `refreshEntries` runs its `refilter(anchor, true, hadPendingResume)` (which consumes `pendingResume`) before `refreshGenres()` is even started. Genre checks are kept across folders ("last until the app quits"), so opening a folder with e.g. `Sports` checked filters the new folder against the previous folder's map. None of the new paths are in it, so every file counts as `Unknown` and the strip goes empty (or shows every file if `Unknown` is checked). Because `pendingResume` has already been cleared, the folder's remembered last-viewed file is lost, and when `genres_of` returns, `refilter(files[index], true)` runs with no anchor and lands on the first passing file. Suggested fix: clear `fileGenres` in the folder-open path. Then, while the Genre section is visible and `shownGenres` is non-empty, make sure the first refilter that consumes `pendingResume` already has the new folder's genres. One way is to fetch `genres_of` together with `folder_entries` (e.g. `Promise.all`) on that read. Another is to keep `pendingResume` until the genres have arrived. Add a test for this if the resume logic can be reached from a unit test (e.g. via `firstEntriesAnchor`).
