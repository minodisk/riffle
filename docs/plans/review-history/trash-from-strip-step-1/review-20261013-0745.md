### Findings

1. **[crates/app/src/commands.rs:2766-2789 / crates/app/src/trash.rs:428-443]**: `trash_files` trusts that every entry of `paths` lives in `dir` (the doc comment states it as a precondition) but never checks it, and `groups_of` → `sidecars_of` matches sidecars by lowercased **file name only** against `dir`'s listing. A path from another folder that shares a stem with a RAW in `dir` (e.g. `dir = /A`, `paths = ["/B/x.ARW"]` while `/A/x.xmp` exists) would therefore move `/B/x.ARW` together with `/A/x.xmp`, an unrelated file's judgment, to the Trash. This is a destructive command, and Step 2 routes it through the idle gate (the press can sit until a scan ends, while the open folder can change), so a mismatched `dir` / `paths` pair is not far-fetched. Make the invariant hold in the backend: in `groups_of` (or `trash_files`), compare each path's parent with the canonical `dir` and attach sidecars only when they match, otherwise report the path as a `Failure` (e.g. "not in the folder") without moving it; or drop the `dir` parameter and list each path's own parent instead. Add a case for a foreign path to `files_are_grouped_with_the_sidecars_that_exist_for_raws_only` or a sibling test.

### Fixed

1. `trash::groups_of` now takes `dir`, groups only paths whose canonical parent is `dir`, and returns the others as `Failure`s ("not in the folder"); `trash_files` appends them to `summary.failed` without moving them. Added `a_file_of_another_folder_is_not_grouped_with_the_sidecars_of_the_folder`; plan.md and learnings.md updated.
