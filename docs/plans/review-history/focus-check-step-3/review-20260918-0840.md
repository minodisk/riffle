## Round 1

**Reviewed commit**: `b6da4855c28460c7d74b20bbfbcee6d549595513` feat(app): toggle a 1:1 focus check with Space

STATUS: NEEDS_FIX

### Findings

1. **crates/app/ui/src/main.ts:295-303 (`drawZoom`)**: the rotation applied to the crop comes from `shown?.orientation ?? 1`, but the crop's own Orientation is carried in the payload header at offset 2 (`crates/app/src/commands.rs`, `crop_payload`) and is currently ignored. The backend already sized the crop with that Orientation (`crop_size` swaps the axes for 6/8), so whenever `shown` is `null` or still holds the previous file, the crop is rotated by the wrong amount. The reachable path: open a folder (or page) while `zoomed` is true — `openDirectory` sets `shown = null`, and a crop that resolves before the preview decode is then drawn unrotated on an Orientation 6/8 file. Store `header.getUint16(2, true)` in the `crop` record and rotate by that, falling back to `shown` only for the placeholder.

2. **crates/app/ui/src/main.ts:310-325 (`drawZoom` placeholder)**: the placeholder mixes two files. `show()` bumps `seq` but leaves `shown` pointing at the previous file's bitmap, while `focus` is read from `entries.get(files[index])` — the new file's focus point. So while paging with the view zoomed, the previous file's preview is drawn positioned by the next file's focus point. Guarding the placeholder the same way the crop is guarded (draw it only when `shown` belongs to the current `seq`, e.g. by tagging `shown` or skipping the placeholder while a preview is outstanding) keeps it honest; blank is better than misplaced.

3. **crates/app/ui/src/main.ts:392-406 (`toggleZoom`)**: with no folder open, `Space` still flips `zoomed`, and `setStatus(zoomed ? "1:1" : undefined)` overwrites the opening hint (`Press "o" or click "Open folder".`) and never restores it — after one toggle off, the note is gone for good. `requestCrop()` already no-ops on `files.length === 0`; make `toggleZoom()` return early in the same case.

4. **crates/app/ui/src/main.ts:399-401 and 469 (status vs. mode)**: `show()` calls `setStatus()` unconditionally, which clears the `"1:1"` note while the view is still zoomed, and `requestCrop`'s `catch` replaces it with the error text. The indicator therefore reports the mode only until the next page turn. Either drive the note from `zoomed` inside `setStatus`/`renderMeta`, or drop the `"1:1"` note entirely rather than leaving it half-maintained.

5. **crates/app/ui/src/main.ts:470**: `if (zoomed) requestCrop();` is the only unbraced single-line `if` in the file; every other branch here uses a block. Prettier will not add the braces, so this stays as a local style deviation — wrap it in a block.

6. **crates/app/ui/src/main.ts:327-339 (`requestCrop`) / 705 (`resize`)**: the crop is requested with the viewport size at request time, but `resize` only calls `draw()`. After enlarging the window while zoomed, the held crop is smaller than the viewport and the (mis-scaled) placeholder shows around it, with no way to refresh short of paging. A one-line `if (zoomed) requestCrop()` in the resize path (or invalidating `crop` on resize) closes it; if this is deliberately deferred, record it in `learnings.md` next to the other deferred items rather than leaving it silent.

7. **crates/app/ui/src/main.ts:344-347, 364-367, 375-378 (`requestCrop` stale retry)**: the retry fires even when `zoomed` has since been toggled off, spending a full round trip on a view that is not showing. Gate the retry on `zoomed`.

### Findings

1. **crates/app/ui/src/main.ts:327-339 (`requestCrop`) / 729-734 (`resize`)**: the resize hook added for Round 1 item 6 is dropped whenever a request is already outstanding (repeat of Round 1 item 6, partially). `requestCrop()` returns early on `cropInFlight`, and the stale-retry branches only fire on `current !== seq`, which a resize does not change. Dragging the window larger therefore issues one request at the first resize event and silently discards every later one, so the crop keeps the size it had when the drag started and the mis-scaled placeholder shows around it until the next page turn. Record the requested viewport size on the `crop` record (or set a `cropPending` flag on resize) and re-issue when the settled crop no longer matches the current `canvas.client*` size. The same check would also let `toggleZoom()` refresh a crop that was cut for a stale viewport.
