1. **[crates/app/ui/src/main.ts:3112-3122]**: When the Compare view is open (`comparing`), a score that arrives for one of the compared frames never reaches the screen. `drawCompare()` reads the `sharpness` map for each label's score suffix and for the green `BEST` bar, but the handler calls `draw()` only when `current` is true. `current` comes from `applyFaceReady`, which skips a file with no focus point, and it covers only `files[index]`, not the other compared frames. If the user opens Compare on a burst while the pass is still at `analyzing N / M`, the labels show no scores and no `BEST` until something unrelated triggers a redraw. The plan's Done-when says the scores feed "the strip bars and the compare order". Fix: keep the result of `applySharpnessReady` and redraw on it when comparing, e.g. `const scored = applySharpnessReady(...); if (scored) applySharpness(); ... if (current || (scored && comparing)) draw();`.
