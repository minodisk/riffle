### Findings

1. **[crates/app/ui/src/main.ts:1189-1244]**: `drawFaceMarks` draws the faces of `files[index]` over whatever `shown` holds, and `shown` is still the previous file's bitmap between `show()` and the new preview's decode. The response handler in `requestFaces` makes this reachable: it calls `draw()` as soon as `files[index] === path`, and a detection takes about 30ms, so it can easily land before a slow preview decode. For example, page from A to B with `f` on. A `draw()` from `refreshEntries` during a scan, a resize, or toggling `f` requests B's faces. When they come back, `draw()` paints B's boxes on A's image, scaled by B's preview size onto A's `drawWidth` / `drawHeight`. That stays visible until B decodes. The AF mark already had this mismatch only on incidental redraws. This change adds a redraw driven by the new response itself. `drawZoom` already guards the same case with `shown.seq === seq` (main.ts:1261). Do the same here: skip drawing, and optionally skip the request, when `shown === null || shown.seq !== seq`. The worker's decode then runs `draw()` again and draws the faces on the right bitmap.
