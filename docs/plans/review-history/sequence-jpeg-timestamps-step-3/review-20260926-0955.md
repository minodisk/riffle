## Round 1

**Reviewed commit**: `4bd152a6bc33a115470fe28677bc5796ba4cfc23` feat(app): add the Sequence JPEG Timestamps dialog with preview, progress and cancel

STATUS: NEEDS_FIX

### Findings

1. **crates/app/ui/src/main.ts:2826 / crates/app/ui/src/main.ts:598**: The mutual exclusion between the two modals has a gap while the flow is in `picking` / `previewing`. `sequenceFlow.isOpen` is false in those phases, so `open-settings` (gated only on `sequenceFlow.isOpen`) can open the settings modal while `sequence_preview` is still in flight. A preview can take a while on a large export folder. When the preview resolves, `sequenceFlow.previewed()` succeeds and `showSequencePreview` un-hides `#sequence-dialog` and calls `.focus()` on its Run button, even though settings is open. The result is two modals open at once. `#sequence-dialog` comes earlier in the DOM with the same `z-index: 30`, so it sits under settings, but focus has moved into it, and keydown still goes to `settings.keydown` first. This breaks the invariant the rest of the diff sets up (`sequenceTimestamps` refuses while settings is open, and `open-settings` refuses while the sequence dialog is open). Fix: add a "busy" check on `SequenceFlow` (phase not `idle`/`done`) and use it in the `open-settings` gate, or have the preview `.then` end the flow (`sequenceFlow.fail()`) instead of showing the dialog when `settings.isOpen || !formatDialog.hidden`. Also add a `sequence.test.ts` case for whichever state-machine method you add.
