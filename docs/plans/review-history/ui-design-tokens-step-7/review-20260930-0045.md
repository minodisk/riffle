### Findings

1. **[docs/agents/ui-styling.md:134-156]**: The pre-PR check and the exception list do not match what `style.css` actually contains. The `style.css` grep matches only hex (`'#[0-9a-f]{3,6}\b'`), so it misses every `rgb()` / `rgba()` literal. Two consequences follow. (a) The exception it lists for the burst band tint (`.cell.burst::before`'s `rgba(255, 255, 255, 0.08)`, style.css:869) never shows up in the grep it is supposed to explain. (b) The component block has literal colors that are neither tokens nor listed exceptions: the `rgb(255 255 255 / 4.5%)` fill of `.button.outline` / `.input` / `.select` (style.css:139, 154), the `.dialog` backdrop's `rgb(0 0 0 / 60%)` (191), and the `rgb(0 0 0 / 50%)` shadows of `.dialog-box` / `.menu` (200, 221). "Never an ad-hoc color" together with "check every match is `:root` or listed above" gives a future contributor no way to tell whether these count as violations, and a new ad-hoc `rgb(...)` in `style.css` would pass the check unnoticed. Suggested fix: extend the CSS grep to `'#[0-9a-f]{3,6}\b|rgba?\('`, the same as the `.ts` grep, and add these component-block values to `## Exceptions` with a short reason for each. For example, 4.5% is shadcn's `input/30` over the dark background, and the backdrop and shadows are black overlays with no shadcn token.
