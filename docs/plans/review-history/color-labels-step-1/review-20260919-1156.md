### Findings

1. **[crates/core/src/xmp.rs:210-214]**: The element-form value range is only the first `Event::Text`, so any value that contains an entity reference ends up truncated. quick-xml 0.42 (the version in Cargo.lock) emits `&amp;` / `&#x...;` as separate `Event::GeneralRef` events. For `<xmp:Label>Red &amp; Blue</xmp:Label>`, `read_label` returns `"Red "` and `write_label(.., Some("Green"))` produces `<xmp:Label>Green&amp; Blue</xmp:Label>`, which corrupts a foreign label. Labels are free text kept "as-is so any vocabulary round-trips", so they are much more exposed to this than ratings. Suggested fix: extend the range across every Text/GeneralRef event until the matching End, e.g. set `start` on the first event and keep updating `end`. Simpler still: since the End event is awaited anyway, use `open_tag_end..pos` of the End event as the value range. Add a test with an `&amp;` element value covering both read and set.
2. **[crates/core/src/xmp.rs:10]**: The edited module doc line runs to about 110 columns, while the rest of the doc is wrapped at about 78. rustfmt does not wrap comments, so re-wrap it by hand.
