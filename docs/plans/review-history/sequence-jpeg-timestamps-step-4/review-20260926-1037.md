## Round 1

**Reviewed commit**: `603e627f29956a5c078a83afebd6684cfab100dd` docs: document the Sequence JPEG Timestamps workflow

STATUS: NEEDS_FIX

### Findings

1. **[docs/usage.md:217-219]**: "Progress and cancel" first describes canceling, then says "At the end the status line shows `Wrote N of M files to <folder>-sequenced`". That is only the uncanceled case. `doneStatus` in `crates/app/ui/src/sequence.ts:59-64` shows `canceled, N of M written` after a cancel, and adds `, K failed` whenever a file failed. A reader who canceled will not see the documented line. Suggested wording: "At the end the status line shows `Wrote N of M files to <folder>-sequenced`, or `canceled, N of M written` after a cancel, followed by `, K failed` when some files failed."
2. **[docs/usage.md:220-221]**: "a file whose `DateTimeOriginal` cannot be read ... sorts last in the preview and is listed there" suggests the file shows up as the last row of the ordered `old -> new` list. It does not. `preview` in `crates/app/src/sequence.rs:103-113` moves it out of `rows` and into `failed`, and the dialog lists it separately under the count line, as `name: reason` (`#sequence-failed`, `failureText`). The preview also disables `Run` when no file could be read (`crates/app/ui/src/main.ts:635`). Suggested wording: "...gets no new time and no copy; the preview lists it below the order with the reason (and `Run` is disabled when no file could be read)." For consistency, the "Preview" bullet (lines 201-204) could mention the notice shown when `<folder>-sequenced/` already exists ("will be rebuilt: its JPEG files are replaced", `rebuildNotice`), since that is the one piece of dialog text left undocumented.

### Findings

1. **[docs/usage.md:224-228]**: "A file that fails when the run itself writes ... is listed the same way" comes right after "the preview lists it below the order", so it reads as though run failures also show in the dialog. They do not: `finishSequence` in `crates/app/ui/src/main.ts:672-682` closes the dialog first and then adds each failure to the error list at the bottom of the right pane (`errors.add(failure.path, failureText(failure))`). A folder-level error at run time (no JPEGs left, or an output folder that is refused or cannot be rebuilt) goes there too, as the one failure keyed by the folder (`crates/app/src/sequence.rs`, the `Err` arm of `sequence_run`). By contrast, a folder-level error at preview time (for example a folder with no JPEGs) only reaches the status line (`.catch` in `sequenceTimestamps`, `main.ts:603-606`). Suggested wording: "A file that fails during the run, because it could not be read or written, is listed as `name: reason` in the error list at the bottom of the right pane once the dialog closes, and the other files are still written." Optionally, make the "Files" bullet's "A folder without any is an error" say where that error appears (the status line).
