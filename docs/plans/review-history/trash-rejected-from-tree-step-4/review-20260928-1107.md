### Findings

1. **crates/app/ui/style.css:1015 (`#sequence-failed, #trash-failed`)**: `#trash-failed` has no scroll and no `min-height: 0`, so in the flex column of `#trash-box` (capped at `max-height: 85vh`) a long failure list grows past the box and pushes `Move to Trash` / `Cancel` below the viewport. This is likely in the trash dialog, unlike the sequence dialog: a recursive run over a year folder on a share with permission problems, or a folder whose sidecars fail to parse, gives one failure per file. The worst case is zero rejects with failures, where the failure list is the dialog's only content. Give `#trash-failed` its own `overflow-y: auto; min-height: 0;` with a bounded height (for example `flex: 0 1 auto; max-height: 30vh`), or let it share the scrolling region with `#trash-rows`, so the buttons stay in view.
2. **crates/app/ui/src/trash.ts:827 (`emptyFoldersLine`)**: the line always says "N **more** folders with no rejects", even when no folder rows are shown above it. Two cases hit this: the zero-rejects-with-failures dialog, which the learnings call out as a supported case, and a preview in which every folder read has no rejects. Then the dialog reads "1 more folder with no rejects" with nothing before it. Drop "more" when `folderRows(preview)` is empty (for example "1 folder with no rejects"), and add a test case for it next to the existing `emptyFoldersLine` tests.
