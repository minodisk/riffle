## Round 1

**Reviewed commit**: `b25f3133b08cebe9790b76f35338f03e601d2b0e` feat(app): open a flag context menu on right-click in the strip

STATUS: NEEDS_FIX

### Findings

1. **[crates/app/ui/src/main.ts:1921-1929]**: While the context menu is open, the keydown listener still sends every other key to `runAction`. So an arrow key (or any keyboard action that changes `index`) moves to another file, but the menu stays open at the old pointer position. A later click on Reject / Pick then applies to the new current file, not the cell the user right-clicked. Fix: when `!contextMenu.hidden`, close the menu before sending the key on (e.g. call `closeContextMenu()` right before `const action = keymap.get(key)`). Another option is to swallow keys while the menu is open. Either way, a menu item can then only ever act on the cell it was opened for.
