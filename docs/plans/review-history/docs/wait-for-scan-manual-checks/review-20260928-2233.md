A tree rename of some other folder just calls `folders.renamed`, and `renameFile` never reopens (it patches `files` in place). As written, someone running the check by hand on an unrelated folder would see a false failure. Scope the clause, for example "and, when the renamed folder is the open one (or contains it), the folder reopens at the new path; a file rename keeps the cell's marks under the new name".
