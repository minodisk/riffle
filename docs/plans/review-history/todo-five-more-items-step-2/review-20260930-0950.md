### Findings

1. **[crates/app/ui/src/main.ts:2643 / 2859]**: `lastScanAt` is stamped only in `startScan`, but a focus-triggered `resync()` reaches `startScan` only after its `list_arw` round trip resolves. A second `tauri://focus` inside that window (alt-tab away and back while the first rescan is still listing, which on a large or network folder can take hundreds of ms or more) still sees the old `lastScanAt`, passes `focusRescanDue`, and hits `resync()` while `resyncInFlight` is true. That sets `resyncPending`, so `drainResync()` runs a second full rescan (list + `scan_folder` + `start_scan`) once the first finishes. The throttle then misses exactly the case it targets. Fix: also stamp `lastScanAt = Date.now()` in the focus listener right before it calls `resync()` (or have the listener track its own last-trigger time), so the interval is measured from the trigger and not only from the eventual scan start. Update the comment on `lastScanAt` and the Step 2 note in `learnings.md` to match.
