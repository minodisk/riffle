## Round 1

**Reviewed commit**: `8efaeafbfee33a28a2a4336f2ed300f21e18dcca` feat(cli): add the embed prototype and measure the candidate embedding models

STATUS: NEEDS_FIX

### Findings

1. **[crates/cli/src/main.rs:866-870, 926-934 (`embed_cmd`, `--previews`)]**: Each preview is written as `{file_stem}.jpg` in one flat folder, but `embed` takes several input folders (the reference set itself spans four shooting days). Sony names repeat across folders (`_DSCnnnn`), so two sources with the same stem overwrite one JPEG without any warning. `list.tsv` then points both source paths at the survivor, and `ref_embed.py` embeds the wrong image for one of them. The result is a low cosine that looks like a preprocessing bug, or worse, one that goes unnoticed. Fix: bail on a duplicate stem before the run (collect the stems into a `HashSet`), or name each preview by its index or with the parent folder's name. A related point: the write happens inside `load`, so `paths[0]` is written twice (warm-up and run) and the file I/O is counted in the timed "decode" ms. Writing the previews after the timed loop, or leaving `decode` out of the timings when `--previews` is set, would keep the reported numbers clean.
2. **[crates/cli/src/main.rs:1011-1016, 1031-1069 (`dot` / `compare_embeddings`)]**: `dot` zips the two slices, so vectors of different lengths are silently truncated. Comparing two dumps from different models (SigLIP 2's 768-d against OpenCLIP's 512-d), or a truncated TSV line, prints believable cosines and an agreement score instead of failing. This is an easy mistake given the many `<model>.*.tsv` files `models.md` lists. Fix: in `compare_embeddings`, bail when any paired `v.len() != w.len()`, or when rows within one dump differ in length, naming the path. Add a case for this to `embed_lines_round_trip_and_compare_by_path`.
