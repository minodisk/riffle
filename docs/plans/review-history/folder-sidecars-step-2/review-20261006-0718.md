## Round 1

**Reviewed commit**: `3d73a56b2c72c6774e7c01d881c2f1674e9cde06` feat(app): delete a folder's sidecars to the Trash

STATUS: NEEDS_FIX

### Findings

1. **[crates/app/ui/src/main.ts:691-692 (`trashed`, the redo path of a sidecar run)]**: The sidecar branch calls `clearShownJudgments()` whenever the open folder is the target, even when the redo moved nothing. On a redo (`rescan = true`) the index is not cleared, so the strip only gets its judgments back if the follow-up `resync("trash")` triggers a `folder_entries` read. `refreshOnScanDone` skips that read when the scan's `changed === 0 && total === 0`, and that is exactly what happens when every redo move fails for a reason other than "gone", such as a permission error or a locked file. The sidecars stay on disk and the rows stay as they were, so the rescan changes nothing. The strip then shows every file as unjudged even though the index and the sidecars still hold the judgments. The same thing happens to files judged between the undo and the redo, because their sidecars are not part of the run. Fix: only clear the strip when `summary.moved.length > 0`. A move that succeeds makes the rescan's reconcile clear that row, so `changed > 0` and the refresh happens. Alternatively, when the redo moved nothing, follow the clear with `refreshEntries()`.
