2. **[docs/plans/20261020-model-search/modelsearch.md:174, 272]**: The text says "every frame scored by a model that did not see its folder", but that does not hold for `stack`. Its input column is the fit set's held-out `G0` score, which is out of fold only for the frame it scores. When `stack`'s fold holds out folder i, its training rows' `G0` scores came from `G0` models whose training included folder i: folder i's picks in the pick fit set, and the stored `G0` in the discard fit set. The held-out folder therefore reaches `stack` second-hand. For the pick read, that means the held-out folder's picks. The effect is probably small, and the held-out folder's discard labels never enter this way. Still, this is a pre-registration, so it should either (a) say this explicitly for `stack` (and for the label-free combinations, which have no training step and are fine), or (b) fix a nested recipe: within each outer fold, recompute the training folders' `G0` leave-one-folder-out over the remaining folders. Pick one and write it next to the `stack` bullet.
