## Round 1

**Reviewed commit**: `7caf4a734fccd3af4c10819c11b2cdae64c3fff0` feat(app): add the pick flag for .dop sidecars

STATUS: NEEDS_FIX

### Findings

1. **crates/app/src/index.rs:188-195 (`prepare`)**: The v2 -> v3 migration is not atomic. `ALTER TABLE ratings ADD COLUMN pick` and `PRAGMA user_version = 3` run as separate autocommit statements. If the process dies between them, the file is left at `user_version = 2` with the `pick` column already present. On the next open the `ALTER` fails with "duplicate column name", `Index::open` treats that as an unusable cache and deletes the database, and every `dirty = 1` row goes with it. That is exactly the data loss the `SCHEMA_VERSION` doc comment says a bump must avoid. Fix: run the `ALTER` and the `user_version` update in one transaction (both are transactional in SQLite), or skip the `ALTER` when `pragma_table_info('ratings')` already lists `pick`. The doc comment on `Index::open` ("A database written by a different schema version is discarded: it is a cache") is also stale now that v2 is migrated, so update it too.
2. **crates/core/src/dop.rs:1308-1310 (`write_rating` doc)**: The comment still says the caller must never call this with `rating` `None` for a file that has no sidecar. `sidecar::write` now does exactly that for a pick with no stars (`rating.is_none() && !pick` guard, covered by `a_pick_reaches_the_dop_and_survives_a_later_rating`). Reword it to say that an unrated, unpicked judgement on a file with no sidecar must not be written.
