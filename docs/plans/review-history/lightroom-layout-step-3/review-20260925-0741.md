## Round 1

**Reviewed commit**: `7eba187711f0e52407c6039c57b76f7cb3e10204` feat(app): add the folder tree to the left pane

STATUS: NEEDS_FIX

### Findings

1. **crates/app/ui/src/folders.ts:120 (`reveal`)**: `current` is set to the raw `path` handed to `openDirectory`, but `render()` compares it against node keys, which are spelled the way `ancestorsWithin` builds them (the root's spelling plus one separator per level). `ancestorsWithin` deliberately normalizes a trailing separator, a lower-case drive letter and forward slashes (tests "trailing separator or not", "either case", "forward slashes"), yet for any such path the chain is expanded correctly and then nothing is highlighted, and `scrollIntoView` finds no `.current` row. Fix: once the chain is known, set `current = chain.at(-1)` (keeping the raw `path` only for the pre-roots render). Add a test-level note or a case that shows the chain's last element is the key to highlight.
2. **docs/usage.md:16 / crates/app/ui/src/folders.ts:99 (`loadRoots`)**: `folder_roots` is invoked once at launch and never again, so a card or drive inserted after launch (a new `/Volumes/*`, `/media/*/*` or drive letter, all of which are roots) never appears in the tree. Re-expanding only re-lists the subfolders of an already-known folder, so the usage text "again on every expand, so a card inserted since shows up" is not true for the case it names. Either refresh the roots (e.g. re-invoke `folder_roots` and `addRoots` on window focus, or on each `reveal`), or correct the usage sentence (and the code comment above `toggle`) and record root refresh in learnings.md's deferred issues.
3. **crates/app/ui/src/folders.ts:139-147 (`reveal`)**: when `list_subfolders` fails along the chain, the node has already been `expand`ed and is left `expanded: true` with `children: undefined`, so it draws as `▾` with nothing under it, and the first click on its expander only collapses it (a second click is needed to retry). `toggle` collapses on the same failure. Collapse the node in the `catch` too, so both paths leave the same state.
4. **crates/app/ui/src/tree.ts:18-21 (path-keyed nodes)**: a folder reachable from two roots shares one node, e.g. on Windows the home root `C:\Users\me` and `C:\` > `Users` > `me` (Step 2 keeps both on Windows), or any root under the `/` that `rootOf` adds. Expanding either row expands both, and the subtree and the `.current` highlight are drawn twice. The plan asked for a map keyed by path, so this need not be redesigned now, but it is a visible quirk on Windows by default: at least record it in learnings.md's deferred issues (a possible fix is keying `expanded` by the row's root-plus-path, or not listing a root's own path as a child of another root).
