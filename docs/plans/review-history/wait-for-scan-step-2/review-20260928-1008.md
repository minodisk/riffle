### Findings

1. **[crates/app/ui/src/settings.ts:97-100, 439-448]**: The comment's case for skipping `discard()` ("the folder cannot change while the modal is open") only covers the time the modal is open. A held clear outlives `close()`. Escape or the close button leaves `clearGate` holding the clear, and the user can then open another folder. `openDirectory`'s reset path (`main.ts` ~2511) calls `setScanRunning(false)` just before `startScan()`, and that runs `clearGate.drain()` while the backend's old scan still holds `running`. `clear_index` then returns `SCAN_RUNNING`, and the error goes to the status line of the closed modal (the next `open()` clears it). So the clear the user asked for is dropped and nobody sees why. Even when no folder switch happens, closing the modal means `clear_index`'s native "Clear the index cache?" dialog pops up out of context whenever the scan ends. The simplest fix, which also makes the comment's premise true, is to call `clearGate.discard()` and then `updateClearButton()` in `close()`, and to reword the comment to say a held clear lasts only while the modal is open. The other option is to keep the clear held across `close()`, but then the folder-switch path must not drain it: for example, expose a `discardClear()` hook that `openDirectory` calls next to `idle.discard()`. Update the comment and `docs/usage.md` to match whichever you choose.
