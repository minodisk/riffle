### Findings

1. **crates/app/src/folders.rs:50-54**: The "home or one of its ancestors" drop rule removes the Windows system drive from the roots. On Windows the home is `C:\Users\<name>`, which canonicalizes to `\\?\C:\Users\<name>`, and `C:\` canonicalizes to `\\?\C:\`. `starts_with` compares component by component, so it matches and `C:\` is skipped. As a result, nothing on `C:\` outside the home directory (for example `C:\Photos`) can be reached from the tree. The plan asks for every existing drive root on Windows and only for dropping *duplicates*. `C:\` is not an alias of home the way macOS's `/Volumes/Macintosh HD` is. The learnings note ("when home itself lives on an external volume, that volume is not listed separately") describes this as an edge case, but on Windows it happens on every machine. Suggested fix: limit the ancestor rule to the macOS `volumes()` case (or to a volume whose canonical path is `/`), and keep plain canonical-equality dedup elsewhere. Update the learnings entry to match.
2. **crates/app/src/folders.rs:109-118**: Each non-directory entry costs two `stat`s: `path.is_dir()`, then `path.is_file()`. A folder of 5000 ARWs plus sidecars therefore pays about twice the stats that `list_dir` does, and this is the network-share path the plan explicitly wants to keep cheap. Suggested fix: call `entry.metadata()` / `std::fs::metadata(&path)` once per entry and branch on the result. Better still, test `is_raw_file(&path)` by name before stat'ing, so non-RAW files that aren't directories only need the single stat that tells a file from a directory.
