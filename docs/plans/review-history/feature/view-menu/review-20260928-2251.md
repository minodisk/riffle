## Round 1

**Reviewed commit**: `a977edcde843f044211069c23d0799a2cdae56c5` feat(app): add a View menu with the panel and view toggles

STATUS: NEEDS_FIX

### Findings

1. **crates/app/ui/src/main.ts:2685-2690**: The `menu-action` listener is meant to run each View item "under the same gates as the key" (plan Step 1), but it skips two things the keydown path does before `runAction`:
   - (a) The keydown handler returns early while the first-launch sidecar format dialog is shown (`if (!formatDialog.hidden) { ...; return; }` at main.ts:3324). `modalOpen()` does not cover `formatDialog`, so a View item still toggles panels, zoom or compare behind that modal. The `open-settings` listener (main.ts:3292) and `trashRejectedIn` both check `!formatDialog.hidden` explicitly for this reason.
   - (b) The keydown path calls `closeContextMenu()` when the strip's HTML context menu is open (main.ts:3360-3362). A native menu click never reaches the webview's `mousedown` closer (main.ts:2184), so the HTML context menu stays open after, for example, `View > Compare`. Its items were built from the pre-toggle `comparing` state (`openContextMenu` picks `compareActivePath` when comparing), so they can now target the wrong file.

   Suggested fix: return when `!formatDialog.hidden`, and call `closeContextMenu()` before `runAction(payload)`, matching what `open-settings` does.
2. **docs/agents/tauri-app.md:385-388**: "`View` is the one submenu the app creates" is wrong on Linux. The same section already says Linux's default menu has no `File` (prepended there), and `build` also creates `Help` when it is missing. Reword it, e.g. "`View` is created on Windows and Linux (the default menu has none there) and inserted right after `Edit`…", so it does not contradict the paragraph above.
