## Round 1

**Reviewed commit**: `66fd750bf5b86ce1d0c398bc5d2278023ac7466e` feat(skills): add the delegate skill that hands a task to a new herdr worktree

STATUS: NEEDS_FIX

### Findings

1. **[.claude/skills/delegate/SKILL.md:73]**: `herdr agent prompt <name> "/develop <task description>"` puts the description in a double-quoted Bash string, and the skill runs it in Bash. Step 4 also asks for a detailed description that names the related files. Those names are usually in backticks (e.g. `` `src/filter.ts` ``), so Bash runs them as command substitutions, and any `$VAR`, `"` or `\` in the text gets expanded or ends the string early. The new session then receives a mangled task, or a command runs when nobody meant it to. Fix: pass the text through a quoted heredoc, e.g. `herdr agent prompt <name> "$(cat <<'EOF'` / `/develop <task description>` / `EOF` / `)"`. Also say that the description goes in verbatim, with nothing escaped.
2. **[.claude/skills/delegate/SKILL.md:15-21, 56-66]**: The skill says "if a command fails, re-check [the help] rather than guessing" but never says what to do when step 3 or 4 fails after step 2 has already created the worktree and workspace. A model that retries from step 2 creates a second worktree for the same task. Add one line: after `herdr worktree create` succeeds, never run it again; retry `agent start` / `agent prompt` against the same `<pane_id>`. If they still fail, report the leftover worktree and workspace ID to the user. Following herdr's own rule, do not close them without asking.
