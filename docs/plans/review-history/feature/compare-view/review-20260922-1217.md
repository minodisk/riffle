### Findings

1. **[crates/app/ui/src/main.ts:782]**: Comparison candidates can still change without reloading the comparison (repeat of Round 1 item 1). `refreshEntries` replaces `sharpness` and `bursts` before calling `refilter`, but when the visible file list is unchanged this early return leaves `compareFrames` showing the old best candidate; during an incremental scan, a newly indexed sharper burst frame can therefore update the `Compare · N frames` text while never appearing in the viewer. The stationary branch of `extendSelection` at line 1501 has the same problem when a boundary keypress changes the range without moving focus. Refresh comparison state whenever its candidate inputs change, including these no-list-change/no-focus-change paths, and cover those integrations rather than only the pure `reconcileActive` helper.
2. **[crates/app/ui/src/main.ts:650]**: `Promise.all` loses already-created `ImageBitmap`s when any one of the 2–4 preview loads or decodes rejects. The catch reports the error but cannot close fulfilled sibling results, and siblings that finish after the aggregate has rejected are likewise never closed, so repeatedly comparing a set containing one bad RAW leaks full-preview bitmaps. Wait for all loads with settled results (or otherwise retain every successfully created bitmap), close all successes on any failure, and then propagate the error.
