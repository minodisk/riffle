### Findings

1. **crates/core/src/arw.rs:472-477**: `sigma_af_point` runs the `at + count > buf.len()` bail before the `count <= SIGMA_HEADER_LEN` check. When a MakerNote has `count <= 4`, its value sits inline in the entry, so `entry.1` is data, not an offset. `maker_note_ifd` returns `Ok(None)` for `count <= 4` without a range check, so nothing upstream guards this case. On a `Sigma BF` file whose MakerNote is tiny, the inline bytes read as an out-of-range offset would bail and fail the whole `parse` (and the file's preview with it), when the right result is `None`. This also means the claim in `learnings.md` ("the only error path is a MakerNote range past the buffer, which `maker_note_ifd` already rejects before the Sigma helper runs") is not quite right. Fix: return `Ok(None)` for `count <= SIGMA_HEADER_LEN` first and range-check only after that, the way `leica_focus_distance` orders its checks (keeping the bail for a real out-of-range offset is fine). A test with a `count <= 4` MakerNote whose value, read as an offset, points past the buffer would cover it. Update the `learnings.md` sentence to match.
