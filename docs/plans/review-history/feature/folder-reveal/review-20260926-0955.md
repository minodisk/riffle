STATUS: NEEDS_FIX

### Findings

1. **crates/app/ui/src/folders.ts:284-288**: The focus guard only looks at `event.button === 2`. On macOS, Control+click is the other standard way to right-click (common on trackpads). WebKit sends it as a `mousedown` with `button === 0` and `ctrlKey === true`, then a `contextmenu`, and no `click`. So the guard does not catch it. The `tabindex="0"` container takes focus, the tree gets the keyboard, and the culling keys turn off without telling the user. The plan's Done-when forbids exactly this ("the culling key gate must not change"). `learnings.md` also records the right-click as never changing focus. Fix: also `preventDefault()` a primary-button `mousedown` with `ctrlKey` on macOS, e.g. `event.button === 2 || (event.button === 0 && event.ctrlKey && isMac)`. Limit it to macOS, because on Windows/Linux Ctrl+click is an ordinary click that opens the row and should still focus the tree. Update the learnings note to match.
2. **docs/plans/20260926-folder-reveal/plan.md:143-145**: Step 1 is ticked `[x]`, but `## Progress` still says `- (none yet)`. The plan's own `<pr-rules>` require the implementation PR to include "marking the step done + the Progress entry". Replace the placeholder with a `- (2026-09-26) Step 1 complete` entry, the format the archived plans use.
