### Findings

1. **crates/app/src/update.rs:52-64**: `running` is cleared (`store(false)`) before `installed` is set in the `Ok(Some(version))` arm. A run that starts in that window (for example, a menu click just as the startup install finishes) passes both the `installed` check (still `None`) and the `compare_exchange`, then downloads and installs the same update again. That is the double download the `installed` field is meant to prevent. Fix: record `installed` before releasing `running`, e.g. set `*index::lock(&state.installed) = Some(version.clone())` inside the match first and clear `running` after the match. Alternatively, check `installed` again after taking the flag.
2. **docs/plans/20260919-silent-auto-update/plan.md:131-133**: Step 1 is marked `[x]`, but `## Progress` still says "(none yet)". The plan's PR rules require the implementation PR to include "marking the step done + the Progress entry". Add a Progress entry for Step 1.
