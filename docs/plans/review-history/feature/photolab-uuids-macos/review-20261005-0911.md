1. **[README.md:249-258, README.ja.md:98-101]**: The user-facing DxO PhotoLab section still says the database lookup is Windows-only ("So on Windows, when Riffle creates a `.dop`..." and "When the database is not found (on macOS, or without PhotoLab installed)..."). 2. **[crates/app/src/photolab.rs:248-249]**: The macOS queries hardcode the Core Data entity numbers (`Z_ENT = 6` for `DOPVolume`, `Z_ENT = 5` for `DOPFolder`). Core Data assigns these numbers per model, and they are recorded in `Z_PRIMARYKEY`. A later PhotoLab model that adds or renames an entity can shift them. `database_path` picks the newest `DxO PhotoLab vN` of any version, so on a PhotoLab 11 (or on the v9 the version scan also accepts) the lookup could quietly miss every file and fall back to virtual copies. The `Z_ENT` predicates are not needed to tell the rows apart: volumes are the only rows with `ZPARENT IS NULL`, and folders are reached through `ZPARENT = ?`. Either drop them (roots `WHERE ZPARENT IS NULL AND ZTYPE = 2`, children `WHERE ZPARENT = ? AND ZNAME = ?`) or resolve the numbers from `Z_PRIMARYKEY` by `Z_NAME` (`'DOPVolume'` / `'DOPFolder'`). Then add a fixture case with different `Z_ENT` values, and update the `docs/agents/photolab.md` bullet.
