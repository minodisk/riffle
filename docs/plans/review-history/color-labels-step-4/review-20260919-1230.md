### Findings

1. **[crates/app/ui/src/main.ts:551-557]**: This change can erase existing labels. `labels` is only filled for paths that are not in `touched`. `touched` is added to in `judge()` and is only removed from when the `set_rating` call fails. Suppose the user judges a file before its `folder_entries` row arrives. This happens on a first open while the scan is still indexing, or before the first `refreshEntries` resolves. In that case `judge()` sends `label: null`. Then `set_rating` stores no label and the writer strips the label that PhotoLab or Lightroom put in the sidecar. After that, every later refresh skips the label because the path is still in `touched`, so each further keypress sends null again. Before this step the writer never changed labels, so this data loss is new. The frontend never changes a label on its own in this step, so the `touched` guard does not need to cover `labels`. Update `labels` from every row whether or not the path is touched. Also make sure an unknown label cannot clear the sidecar. One way is to skip `label` in the invoke (or send a "keep" marker) when `entries` has no row for the path yet, and have `set_rating` keep the stored label in that case. Add a test for "judge before the row is known" that checks the label is kept.
