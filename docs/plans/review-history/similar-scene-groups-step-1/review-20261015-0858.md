### Findings

1. **[docs/plans/20261015-similar-scene-groups/groups.md:79-81 vs :178-185]**: The pre-registration contradicts itself on when the fallbacks run. "Grouping rule candidates" says they are evaluated "only if no chained rule that meets the precision bar also meets the recall bar". That condition is vacuously true when *no* chained rule meets the precision bar, so under that reading the fallbacks run in that case. "Selection rule" says that case simply fails ("If no chained rule meets the precision bar, it fails"), and runs the fallbacks only when the selected rule fails the recall bar. This section is frozen once merged, so the ambiguity has to be resolved now. Reword line 79 to match the Selection rule (e.g. "evaluated only if at least one chained rule meets the precision bar and none of those meets the recall bar"). The plan's own wording at plan.md:184-186 ("only if the chained rule fails the recall bar") points the same way.
2. **[docs/plans/20261015-similar-scene-groups/groups.md:60-63 vs :72-77]**: "A frame without a vector or a capture time ... stays its own group" conflicts with the chained rule's "a frame of the same 1 s burst ... always joins (the burst is the atom and is never split)" when a frame has a capture time but no vector and sits inside a multi-frame burst. The rule also leaves open what happens when the open group's last frame has no vector: does the next burst always open a new group (the chain breaks), or is the cosine taken against the last frame that has a vector? Both choices change the coverage number, and Step 4's `scene.rs` will have to match. Fix both here, e.g. "a frame without a capture time stays its own group; a frame without a vector keeps its burst, and a burst whose boundary frame lacks a vector does not chain", matching plan.md Step 4 ("a burst without vectors or capture time stays its own group").
3. **[docs/plans/20261015-similar-scene-groups/plan.md:397-399]**: The plan's pr-rules require "the plan.md update (marking the step done + the Progress entry)" in the implementation PR. The checkbox is ticked, but no Progress entry was added. Add `- (2026-10-15) Step 1 complete`, as the archived plans do.
4. **[docs/plans/20261015-similar-scene-groups/groups.md:133-137]**: "as the archived `pairs.py` `draw` does" is inaccurate. `draw` picks a folder uniformly among folders with *any* candidate left in the bin, then tries 50 random candidates for unused files and retries the loop on failure. It also raises when the bin runs out instead of contributing what it has. The rule written here (folders filtered to those with a candidate whose two files are both unused, shortfall reported) is different. Since Step 2 is told to import `pairs.py` for reuse, an implementer could take that clause as license to call `draw` and get a different procedure. Drop the "as ... does" clause or say "adapted from".
