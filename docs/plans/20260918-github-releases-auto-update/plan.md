# Shipping through GitHub Releases with auto-update

## Purpose

Riffle has never been released: `crates/app` is at `0.1.0` in three manifests,
there are no git tags, and the only way to run it is `mise run app`. This work
makes a release a routine event: release-please turns the Conventional Commits
already on `main` into a release PR; merging that PR tags `main`, creates the
GitHub Release, and — in the same workflow run — tauri-action builds installers
for macOS, Windows and Linux and uploads them with `latest.json`. Every build
from the first release onwards carries tauri-plugin-updater, so an installed
copy notices the next release and installs it from inside the app.

Nothing is OS-signed yet (no Apple notarization, no Authenticode); the README
says what that means for a user. And because merging is no longer "nothing is
released", the merge-approval policy in `.claude` is revised to name the new
human gate.

Scope guard: no OS code signing, no separate update server, no release notes
beyond what release-please generates, no update UI beyond "an update is
available / install it", no crates.io publishing of `riffle-core` /
`riffle-cli`.

## Decisions taken at planning time

1. **Versions.** release-please runs the `rust` strategy at the repository root
   (`"."`), because that strategy updates every workspace member's `Cargo.toml`
   *and* the root `Cargo.lock` (a strategy at `crates/app` would look for
   `crates/app/Cargo.lock`, which does not exist, and leave the root lock
   stale). Consequence: `crates/core` and `crates/cli` are bumped in lockstep
   with the app. They are not shipped or published, so their version number
   carries no meaning of its own. `package.json` and
   `crates/app/tauri.conf.json` are bumped through `extra-files` (`json` type,
   `$.version`). Tag format is `vX.Y.Z` (`include-component-in-tag: false`).
   **Step 4 verifies this with a release-please dry run before relying on
   it**; the fallback is `release-type: simple` with `toml` extra-files for the
   three `Cargo.toml` and accepting a stale `Cargo.lock` (see Trade-offs).
2. **macOS architectures: two native builds, no universal binary.** `aarch64`
   on `macos-latest` and `x86_64` on `macos-15-intel`. tauri-action merges the
   platform entries of parallel runners into one `latest.json`.
3. **Bundles.** `bundle.targets` stays `"all"`. Windows produces NSIS and MSI;
   `updaterJsonPreferNsis: true` picks NSIS for `latest.json`. Linux produces
   deb, rpm and AppImage; only the AppImage self-updates, which the README
   states.
4. **The updater signing keypair is generated by the user, once, on their
   machine.** The private key never enters the repository. The public key is
   committed in `tauri.conf.json`.
5. **The release PR is the human gate.** Nothing reaches a user until the
   release PR (branch `release-please--branches--main`, title
   `chore(main): release X.Y.Z`) is merged, and no agent in this repository
   merges that PR.
6. **release-please runs with a fine-grained PAT** (decided by the user at plan
   approval). A PR opened with `GITHUB_TOKEN` triggers no `pull_request`
   workflow, so the required `ci` check would never report on the release PR.
   The user creates a fine-grained PAT scoped to `minodisk/riffle` with
   `contents: write` and `pull-requests: write` and stores it as the repository
   secret `RELEASE_PLEASE_TOKEN`; the release-please job passes it as `token:`.

## Trade-offs and risks

- **PAT lifetime.** Fine-grained PATs expire. When `RELEASE_PLEASE_TOKEN`
  expires the release-please job fails on the next push to `main`; the fix is
  regenerating the token. A GitHub App would avoid expiry but is more setup.
- **Cargo.lock drift.** If the root `rust` strategy does not update the lock
  (fallback `simple`), the release PR leaves `Cargo.lock` one line stale; the
  dry run in Step 4 decides.
- **Universal macOS vs two native builds.** Two native runners are simpler; a
  universal build would need both rustup targets in `mise.toml` and a double
  `mozjpeg-sys` build.
- **Windows: NSIS + MSI.** Keeping `"all"` ships both; NSIS feeds the updater.
- **Approval policy scope.** Step 3 keeps report-only merging for ordinary
  paths and gates only the release-shaping paths. The stricter alternative is
  dropping the standing approval entirely.
- **Unsigned macOS updater.** The updater replaces `Riffle.app` from a tarball
  it downloaded itself, so no quarantine attribute is expected on the updated
  app — only verifiable at the second release.
- **`crates/core` / `crates/cli` bumped in lockstep** (Decision 1), chosen to
  keep `Cargo.lock` in sync, not for meaning.
